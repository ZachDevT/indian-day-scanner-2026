**Scope:** every HTTP endpoint implemented in the ETMS.Api source tree ( `D:\Sreejith\ETMS_API` , working tree of 2026-09-28) and every request / response structure they exchange. Nothing else. **Production base URL:** `https://api.vishwadharma.org` – all full routes below are relative to it. **Sources:** `src/ETMS.Api/Controllers/*.cs` , `src/ETMS.Api.Contracts/**/*.cs` , `src/ETMS.Api/Infrastructure/ApiProblems.cs` , `RateLimiting.cs` , `ScannerDeviceAuthentication.cs` , `src/ETMS.Api.Application/Options/ApiOptions.cs` , `docs/openapi/etms-api-v1.json` (29 paths; all covered).

## **1. Conventions** 

|**Item**|**Rule**|
|---|---|
|Versionin<br>g|URL segment. Every route starts with<br>`/api/v1/`(except<br>`/health/*`).|
|Transport|HTTPS only. Allowed verbs:<br>`GET`,<br>`POST`,<br>`PATCH`,<br>`OPTIONS`,<br>`HEAD`. Plain<br>`http://`is not served on the public host.|
|Request<br>body|`Content-Type: application/json`(UTF-8). Maximum body size 256 KB. A<br>`POST`without parameters must still carry a<br>`Content-Length`(send<br>`{}`), otherwise IIS answers 411.|
|Response<br>body|`application/json`on success;<br>`application/problem+json`on every error.|
|Property<br>names|camelCase. Enum values are**strings**, spelled exactly as listed. Success responses**emit**<br>**`null` properties**; problem responses<br>omit them.|
|Timestam<br>ps|Every<br>`DateTime`is UTC ISO 8601 with milliseconds and<br>`Z`:<br>`2026-10-03T16:14:05.000Z`. Client-sent timestamps may omit<br>milliseconds; a value without<br>`Z`is treated as UTC.<br>`firstEntryLocal`is the only local-time value (event time zone<br>`Africa/Kampala`, format<br>`h:mm tt`, e.g.<br>`7:14 PM`).|
|Identifiers|Tickets:<br>`ticketId`(GUID string). Users: GUID string. Scanner devices: integer<br>`deviceId`. Dinner passes: integer<br>`passId`and<br>`passNumber`. Gates (officer API only): gate code.|
|`X-`<br>`Correlat`<br>`ion-ID`|Optional request header (letters, digits,<br>`-`; ≤ 64). Echoed as response header<br>`X-Correlation-ID`and as<br>`correlationId`in<br>everybody. Generated by the server when absent.|
|`X-`<br>`Device-`<br>`Label`|Optional request header on scanner routes: free label of the phone (≤ 80 chars after sanitising to letters, digits, space,<br>`.`,<br>`-`,<br>`_`,<br>`:`). Recorded, with the client IP, as the device name in audit rows and in<br>`GET /api/v1/scanner/device`.|
|Rate<br>limiting|Per policy (see each endpoint); 429<br>`RateLimited`with<br>`Retry-After`. Scanner routes without a device token are limited**per**<br>**client IP**. Global ceiling 600 requests / minute / IP.|

### **2.1 Officer authentication (JWT) – not used by the scanner app** 

#### **2.1.1** **`POST https://api.vishwadharma.org/api/v1/auth/login` –** production: verified 

Sign in with ETMS web credentials; receive a 15-minute access token and a rotating 7-day refresh token bound to `deviceId` . Auth: none. Rate limit 10 / min / IP; lockout after 5 failures for 15 minutes.

#### **2.1.2** **`POST https://api.vishwadharma.org/api/v1/auth/refresh` –** production: verified 

Exchange a refresh token for a new token pair; the presented token is consumed. Auth: none. Rate limit 30 / min / IP. Responses: **200** `AuthResponse` . **400** . **401** `InvalidRefreshToken` , `RefreshTokenExpired` , `RefreshTokenReused` , `DeviceMismatch` , `AccountInactive` . **429** . 

#### **2.1.3** **`POST https://api.vishwadharma.org/api/v1/auth/logout` – production status unverified** 

Revoke the caller's refresh token(s) and deny the current access token. Auth: JWT. Body optional `LogoutRequest` : `refreshToken` string ≤ 512 (optional), `allDevices` boolean (default false). Responses: **204** . **401** . 

#### **2.1.4** **`GET https://api.vishwadharma.org/api/v1/auth/me` – production status unverified** 

Profile of the authenticated officer, the device bound to the token and the active event. Auth: JWT. Responses: **200** `MeResponse` (9.3). **401** . 

#### **2.1.5** **`POST https://api.vishwadharma.org/api/v1/auth/sessions/revoke` – production status unverified**
